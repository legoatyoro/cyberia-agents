### 1. Résumé des nouvelles techniques détectées  
- **SSRF avancé** : Plusieurs variantes d'encodage (octaux, Unicode, Base64, entités HTML) pour contourner les filtres.  
- **Chaînes RCE/SSRF** : Combinaison d'encodages multiples (ex: `%2525...`) pour exploiter des parsers imbriqués.  
- **CMDI** : Injection de commande via encodage de retours chariot (`%0d%0a`).  
- **SSTI** : Template injection basique (`<%= 7*7 %>`).  

### 2. Patterns émergents  
- **Encodage en cascade** : Utilisation répétée de double/triple encodage URL.  
- **Notations alternatives** : Octaux, Unicode, entités HTML pour masquer les payloads.  
- **Chaînage de vulnérabilités** : Combinaison XXE/SSRF ou RCE/SSRF dans un seul payload.  

### 3. Recommandations pour les WAF  
- **Normalisation stricte** : Décoder/réencoder les requêtes en profondeur avant inspection.  
- **Détection des chaînes d'encodage** : Règles pour repérer les séquences `%25%32%66` (double-encodage).  
- **Blocage des schémmas obliques** : Intercepter les notations octales/Unicode pour `http://` ou `//`.  
- **Validation contextuelle** : Analyser les paramètres en fonction de leur usage (ex: refuser les octaux dans les URLs).  

### 4. Catégories à renforcer  
- **Chaînage de vulnérabilités** : Plus de génération pour XXE/SSRF et RCE/SSRF.  
- **Encodages exotiques** : Payloads utilisant des encodages rares (ex: UTF-7, compression).  
- **SSTI complexes** : Injections multi-contextes (Twig, Jinja2, etc.).  

*Priorité : SSRF et chaînages, suivis par les encodages obscurs.*
